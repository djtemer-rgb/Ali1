# Архитектура проекта «Путь героя» (Ali Quest)

Проект представляет собой приватный семейный дашборд для двух детей — Али и Саида. Разделён на клиентскую часть (панель детей) и административную часть (панель родителей), защищённую PIN-кодом.

## Структура папок

- **`/app`** — Next.js App Router (страницы и серверные API-маршруты).
  - **`/app/page.tsx`** — основной дашборд детей (выбор профиля, список задач, баланс звёзд, магазин наград, бонусные игры за серию дней).
  - **`/app/parent`** — дашборд родителя (просмотр прогресса, управление начисленными наградами и инбоксом уведомлений).
  - **`/app/settings`** — панель настроек (создание и редактирование задач, настройка наград, интервалов восстановления сердечек, Telegram-уведомлений и PIN-кодов).
  - **`/app/schedule`** — календарь расписания и шаблонов задач по дням недели.
  - **`/app/grades`** — панель ввода школьных оценок.
  - **`/app/components`** — переиспользуемые UI-компоненты (формы ввода, карточки задач) и файлы пяти бонусных игр.
  - **`/app/api`** — серверные API-маршруты.
- **`/lib`** — общая TypeScript-логика проекта.
  - **`upstash.ts`** — подключение и методы для работы с базой данных Upstash Redis.
  - **`streak-utils.ts`** — чистые функции расчёта серии дней и расхода/восстановления сердечек.
  - **`notifications.ts`** — отправка Telegram-сообщений и Web Push уведомлений.
  - **`settings-shared.ts`** — чтение конфигураций настроек для детей и родителей.
  - **`reporting.ts`** — генерация отчётов о прогрессе.

## Слой данных (Upstash Redis)

Используются следующие ключи в Redis:
- `aq:settings` — общие настройки (PIN-коды, Telegram-токены, интервалы).
- `aq:child:ali:profile`, `aq:child:said:profile` — профили детей (базовые данные, аватары).
- `aq:day:ali:YYYY-MM-DD`, `aq:day:said:YYYY-MM-DD` — состояние выполнения задач на конкретный день.
- `aq:star-ledger:ali`, `aq:star-ledger:said` — книга транзакций звёзд (получение за задачи, списание за награды, бонусы).
- `aq:streak-progress:ali`, `aq:streak-progress:said` — состояние серии (текущая серия дней, дата последнего выполнения, оставшиеся сердечки, дата начала восстановления сердечка).
- `aq:events:parent` — список уведомлений для родительского инбокса.

### Важные ограничения:
- **Разделение данных**: данные Али и Саида полностью разделены на уровне ключей Redis.
- **Срок хранения**: данные хранятся за последние 90 дней (старые ключи очищаются регулярным скриптом через `/api/cleanup`).

## Безопасность и Сессии

- **Доступ родителей**: защищён PIN-кодом (хранится хэш в Redis, сессия записывается в зашифрованные cookie-файлы через JWT).
- **Секретные ключи**: переменные среды (`UPSTASH_REDIS_REST_URL`, `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY`) доступны исключительно на сервере и никогда не передаются в браузер (отсутствует префикс `NEXT_PUBLIC_`).

## Узкие места и оптимизация

1. **Задержка сети до Upstash**: Next.js App Router выполняет запросы на сервере. При частых переходах рекомендуется кэшировать настройки.
2. **Маршрутизация в Vercel**: Прямое открытие URL-адресов (например, `/settings` or `/parent`) должно корректно обрабатываться Next.js без ошибок SPA-клиента (за это отвечает файл `middleware.ts`).
3. **Надёжность сохранения при закрытии приложения (keepalive: true)**:
   Дети часто закрывают вкладку браузера или PWA-приложение сразу же после нажатия на чекбокс задачи или после победы в бонусной игре. В обычных условиях браузер отменяет (abort) незавершенные fetch-запросы.
   Для предотвращения потери данных во все POST-запросы сохранения состояния (задачи, звёзды, события, статус игр, оценки) добавлен параметр `{ keepalive: true }`. Это гарантирует, что браузер завершит передачу запроса даже после закрытия вкладки или сворачивания PWA.
