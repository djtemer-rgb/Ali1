## Что уже подтверждено как рабочее направление

Ниже зафиксированы пункты, которые уже обсуждались и были приняты как направление.

### 1. Главный экран

- Карточки должны стать плотнее.
- На карточках задач заголовок показывается максимум в 2 строки, затем многоточие.
- На главной отдельный клик по карточке открывает подробности.
- Отдельная зона завершения задачи должна оставаться доступной.
- Для задач с подзадачами клик открывает подробности и список подзадач.
- Подзадачи должны быть видны внутри карточки или в модалке с полным текстом, без потери смысла.
- Расписание на главной показывается только по активным дням.
- Пустые дни недели не должны занимать место.
- Блоки задач, расписания и магазина должны стать чуть компактнее, без большого воздуха по краям.

### 2. Настройки задач

- Каждая задача должна жить как редактируемый шаблон.
- У шаблона есть active / inactive состояние.
- В шаблоне можно редактировать заголовок, категорию, звёзды, дни повторения, время и детали.
- Подзадачи редактируются прямо в форме шаблона, а не в отдельной абстрактной системе.
- Есть включение/выключение шаблона.
- Есть удаление шаблона.
- Есть inline-редактирование и добавление новых подзадач.

### 3. Подзадачи

- Пользователь хотел модель “шаблон + дневное состояние + подзадачи”.
- Выполненные подзадачи должны сохраняться между refresh.
- Если ребёнок вышел и вернулся к незавершённой задаче, прогресс должен восстановиться.
- Завершение полной задачи возможно только после завершения всех подзадач.
- Подзадачи на UI можно визуально делить по звёздам, но это именно подсказка интерфейса, а не отдельная бухгалтерия.
- Количество звёзд для подзадач должно распределяться примерно, с возможностью дробных значений.

### 4. Расписание

- На главной отображаются только активные дни недели.
- Если дни выключены, они схлопываются и не занимают место.
- Название задачи в расписании должно переноситься минимум в 2 строки.
- Расписание должно быть компактным и не раздувать страницу.

### 5. Parent access

- После logout `/settings` не должен оставаться доступным без повторного PIN.
- Parent area должна защищаться повторной проверкой сессии.
- Никаких тяжёлых шифровальных сценариев не требуется, но защита от случайного открытия должна быть.
- Доступ без PIN возможен только если сессия действительно жива.

### 6. Rewards

- В обсуждении закрепилась идея резервирования / заморозки звёзд до подтверждения награды.
- Награда должна иметь событие выбора, подтверждения и отмены.
- В истории и в UI должны отражаться эти состояния.
- Пользователь не хочет терять баланс при случайном выборе.

### 7. Telegram и push

- Telegram-уведомления уже работают и это важно сохранить.
- В настройках нужны отдельные тумблеры для разных типов уведомлений.
- Позже нужно сделать web-push как отдельную плашку.
- Telegram не должен ломаться из-за новых настроек.

### 8. Reports

- Страница отчётов должна открываться быстро.
- 7 / 30 / 90 дней должны работать корректно.
- PDF-экспорт должен быть красивым и не ломать кириллицу.
- Не надо использовать “скриншотный” путь, если есть более надёжный серверный вариант.

### 9. Dev / localhost stability

- Проблема с `localhost` была связана не с одной задачей, а с dev-cache / service worker слоем.
- На `localhost` и `127.0.0.1` service worker не должен мешать.
- В dev старый кэш не должен блокировать обновления страницы.

## Первая итерация

Первая итерация должна добить ядро, а не распыляться.

### В фокусе первой итерации

1. Закрыть оставшиеся дырки в сохранении и восстановлении задач.
2. Довести модель шаблонов и подзадач до устойчивого состояния.

4. Убедиться, что `/settings` после logout действительно требует повторного PIN.
5. Не разрушить уже работающую логику Telegram, звёзд и базового dashboard.

### Что уже выбрано как поведение

- Задачи с подзадачами должны открывать детали, но завершаться только через правильный чекбокс / завершение всех подзадач.
- Простая задача должна оставаться простой задачей, без лишней тяжести.
- В настройках каждая задача — редактируемый шаблон, а не одноразовая запись.
- Неактивные шаблоны не должны участвовать в главной странице.
