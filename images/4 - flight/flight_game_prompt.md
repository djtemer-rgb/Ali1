# AliToDo / «Путь героя» — Game 4 Implementation Prompt

## Игра 4: Полёт «Сквозь порталы»

Папка игры: `images/4-flight`

Твоя задача — реализовать четвёртую бонусную мини-игру для проекта AliToDo / «Путь героя» на основе этого MD-файла и четырёх PNG-скинов, которые лежат рядом в этой же папке.

Игра должна быть встроена аккуратно как продолжение уже реализованных бонусных игр. Не ломай текущую механику проекта, не ломай уже реализованные игры, не делай тяжёлый рефактор без необходимости.

Если фактическая папка в проекте называется иначе, например `Images/4 - flight`, `Images/4-flight`, `public/images/4-flight` или `public/Images/4 - flight`, используй реальную существующую папку четвёртой игры. Главное — работать с папкой `4-flight` / `4 - flight`, где лежат 4 PNG-скина и этот MD-файл.

---

## 1. Участники игры

В этой игре участвуют:

- `6` Ледяной дракончик — Кристалл
- `11` Огненный дракончик — Искрик
- `16` Лесной дракончик — Вердан
- `13` Орлёнок — Скай

Для каждого героя в папке игры лежит отдельный PNG sprite sheet.

---

## 2. Главная идея игры

Это горизонтальная игра-полёт.

Герой летит слева направо.  
Ребёнок нажимает на экран, чтобы герой поднимался выше.  
Если не нажимать, герой плавно опускается вниз.

Цель:
- пролетать сквозь широкие порталы;
- собирать звёзды;
- избегать опасных летящих предметов;
- добраться до финального портала.

Игра должна быть:
- красивой;
- плавной;
- горизонтальной;
- понятной детям 6–9 лет;
- похожей по общему UI на предыдущие бонусные игры;
- не слишком лёгкой, но проходимой за 2–3 попытки;
- короткой: успешное прохождение примерно 30–40 секунд.

---

## 3. Ориентация экрана

Эта игра должна быть **горизонтальной / landscape**.

На телефоне в портретном режиме можно использовать уже существующий экран:

```txt
Поверни телефон
```

Если в проекте уже есть готовая логика landscape-warning из Runner или другой игры — переиспользуй её.

На десктопе игра должна открываться сразу без предупреждения.

---

## 4. Общая стилистика интерфейса

Игра должна использовать общий стиль уже реализованных бонусных игр.

Не нужно заново изобретать стартовые и финальные экраны. Если в проекте уже есть общий game shell / overlay / start screen / success screen / fail screen — переиспользуй их.

### Стартовый экран

Название:

```txt
Полёт «Сквозь порталы»
```

Пример инструкции:

```txt
Нажимай на экран, чтобы взлетать выше.
Пролетай сквозь порталы.
Собирай звёзды и обходи опасности.
```

Кнопка:

```txt
Начать
```

Не используй слова `tap`, `swipe`, `score`, `leaderboard`.

### Во время игры

На игровом экране должны быть:

- крестик `X` для выхода;
- кнопка паузы;
- 3 сердечка / жизни;
- временный счёт звёзд, если он уже используется в других играх;
- чистый интерфейс без перегруза.

### Пауза

При паузе:
- игра останавливается;
- экран немного затемняется;
- по центру большая кнопка Play;
- после нажатия игра продолжается.

### Поражение

Если жизни закончились:

```txt
Пока не получилось
```

Кнопка:

```txt
Начать заново
```

Автоматический рестарт не делать.

### Победа

Если ребёнок долетел до финиша:

```txt
Игра пройдена!
Поздравляю!
```

Кнопка:

```txt
Окей
```

После `Окей`:
- игра закрывается;
- ребёнок возвращается в карточку;
- кнопка бонусной игры становится неактивной;
- состояние карточки: `Игра пройдена`.

## 5. Completion state

Используй уже существующую систему completion state для бонусных игр.

Требования:

- прохождение хранится отдельно по ребёнку;
- Али и Саид независимы;
- прохождение хранится отдельно по карточке / rewardId;
- выход через `X` не сохраняет прохождение;
- проигрыш не сохраняет прохождение;
- успешная победа сохраняет прохождение только для текущего ребёнка и текущей карточки.

Не добавляй:
- постоянные дополнительные звёзды;
- бейджи;
- рейтинги;
- лидерборды;
- сравнение детей.

Игровые звёзды внутри мини-игры — только временный визуальный эффект.

## 7. Формат каждого sprite sheet

Каждый PNG — квадрат 1:1 на хромакейном фоне.

В каждом листе 6 основных элементов:

### Левая часть / левая колонка — 3 позы героя

1. герой летит, крылья в верхнем положении;
2. герой летит, крылья в среднем положении;
3. герой летит, крылья в нижнем положении.

Эти три позы нужны для плавной анимации полёта.

Анимационный цикл:

```txt
крылья вверх → крылья середина → крылья вниз → крылья середина → крылья вверх
```

Не показывай смену кадров резкой. Сделай мягкую смену:
- через короткий crossfade;
- или через плавное frame interpolation / easing;
- или через аккуратную частоту кадров, чтобы анимация выглядела живой, а не как три грубые картинки.

### Правая часть / правая колонка — 3 элемента

1. портал;
2. звезда;
3. опасный предмет.

---

## 8. Как правильно вырезать ассеты

Очень важно аккуратно вырезать PNG по хромакею.

Требования:

1. Убрать хромакей чисто.
2. Не оставлять зелёный / розовый ореол по краям.
3. Не резать грубо по равной сетке, если это обрезает крылья, хвост, лапы, кристаллы, края портала или опасного предмета.
4. Лучше определить каждый объект как отдельный bounding box и сохранить с прозрачным фоном.
5. Добавить небольшой padding вокруг каждого объекта.
6. Сохранять крылья полностью: не обрезать верхние и нижние положения крыльев.
7. Сохранять хвосты, рога, уши, перья, кристаллы и края порталов.
8. Мелкие отдельные искры и далеко летящие декоративные частицы можно не включать в crop, если они мешают чистой нарезке.
9. Главное — чистые читаемые силуэты героя, портала, звезды и опасного предмета.
10. Если какой-то asset режется плохо, всё равно собери рабочую версию, но укажи проблему в отчёте.

## 11. Игровая механика

### Основная механика

- герой летит автоматически слева направо;
- мир движется справа налево;
- ребёнок нажимает на экран, чтобы герой поднимался выше;
- если ребёнок не нажимает, герой плавно опускается вниз;
- нужно пролетать через порталы;
- нужно собирать звёзды;
- нужно избегать опасных предметов и краёв порталов.

### Управление

На телефоне и компьютере:

```txt
Нажатие / удержание / частые нажатия = подъём вверх
Без нажатия = мягкое снижение вниз
```

Выбери наиболее приятный вариант:
- короткий импульс вверх при каждом нажатии;
- или плавный подъём при удержании;
- или гибрид.

Главное:
- управление должно быть мягким;
- ребёнок должен чувствовать контроль;
- игра не должна быть как злой Flappy Bird;
- падение должно быть плавным;
- порталы должны быть широкими.

## 12. Физика полёта

Сделай физику приятной и детской.

Ориентиры:
- мягкая гравитация;
- плавное снижение;
- понятный подъём;
- без резких провалов вниз;
- без слишком сильного рывка вверх;
- широкие окна порталов;
- скорость полёта умеренная.

Если знаешь хорошие параметры для мягкой Flappy-like механики, можешь подобрать их сам.

Можно улучшить:
- силу подъёма;
- гравитацию;
- скорость горизонтального движения;
- расстояние между порталами;
- ширину порталов;
- частоту опасностей;
- расположение звёзд.

Не делай игру хардкорной.

---

## 13. Порталы

Порталы — главная цель игры.

Нужно пролететь примерно:

```txt
10–12 порталов
```

Порталы должны быть:
- достаточно широкими;
- красиво тематическими;
- не слишком частыми;
- визуально читаемыми;
- разными по высоте, но без резких несправедливых скачков.

### Важный момент
Если портал расположен высоко, следующий не должен быть сразу экстремально низко, и наоборот.  
Пусть траектория будет волнообразной и честной.

---

## 14. Звёзды

По пути можно собрать примерно 5 звёзд.

Звёзды:
- дают визуальный эффект;
- могут давать звук;
- считаются только внутри текущей мини-игры;
- не сохраняются в основную систему звёзд;
- не используются для сравнения детей.

Звёзды можно размещать:
- рядом с безопасной траекторией;
- иногда чуть выше или ниже, чтобы ребёнок мог рискнуть;
- но не делать их обязательными для победы.

---

## 15. Опасности

Опасные предметы должны:
- хорошо отличаться от звёзд и порталов;
- быть понятными;
- не создавать безвыходные ситуации.

Типы опасностей:
- ледяной осколок;
- лавовый метеор;
- фиолетовый магический шип;
- красное опасное перо / воздушный шип.

Если ребёнок задел опасный предмет:
- минус 1 сердце;
- короткий эффект удара;
- герой мигает / получает invulnerability примерно на 1 секунду;
- игра продолжается.

Если все сердца закончились — экран поражения.

---

## 16. Жизни

Используй привычную систему:

- 3 сердечка.

Ошибки:
- столкновение с опасным предметом;
- столкновение с краем портала, если это реализовано;
- вылет за допустимые границы экрана, если это есть в механике.

После ошибки:
- минус 1 жизнь;
- короткая защита от повторного мгновенного удара;
- игра продолжается.

Если жизни закончились:
- экран поражения;
- кнопка `Начать заново`.

---

## 17. Финиш

Это не endless-игра.

Нужен понятный финиш:
- финальный большой портал;
- сияющие облака;
- арка;
- звёздный выход;
- или другой красивый финальный объект.

Победа засчитывается, когда герой пролетает финальный портал / достигает конца маршрута.

---

## 18. Фоны и отличие от других игр

Игра должна отличаться от Runner, Hunter, Tap Reaction и Jump.

Можно добавить:
- параллакс-фон;
- мягкие облака;
- сезонные элементы;
- лёгкие частицы;
- тематическое небо под каждого героя;
- мягкое свечение порталов;
- разные цветовые настроения.

Но:
- не перегружать экран;
- не затемнять фон;
- не мешать читаемости порталов, звёзд и опасностей;
- не делать фон важнее геймплея.

Фон должен быть красивым, но игровая информация должна читаться мгновенно.

## 19. Анимация

### Анимация героя

Используй 3 кадра крыльев:

```txt
верх → середина → низ → середина → верх
```

Сделай смену кадров мягкой:
- через easing;
- через короткий crossfade;
- или через достаточно частую и плавную смену кадров.

Не должно выглядеть как грубое переключение трёх картинок.

### Анимация порталов

Порталы могут:
- мягко пульсировать;
- иметь небольшое вращение/свечение;
- слегка менять яркость.

### Анимация звёзд

Звёзды могут:
- мягко мерцать;
- слегка вращаться;
- давать короткую вспышку при сборе.

### Анимация опасностей

Опасные предметы могут:
- слегка вращаться;
- иметь красное/огненное/ледяное свечение;
- двигаться по простой траектории, если это не усложняет игру.

---

## 20. Баланс сложности

Игра должна быть интересной, но не раздражающей.

Цель:
- ребёнок обычно проходит за 2–3 попытки;
- успешное прохождение занимает около 30–40 секунд;
- игра не должна быть суперлёгкой;
- проигрыш должен ощущаться как “попробую ещё раз”, а не как несправедливость.

---

## 24. Финальный принцип

Сделай игру **красивой, плавной, воздушной и понятной**.

Главное:
- горизонтальный полёт;
- мягкая Flappy-like физика без хардкора;
- широкие порталы;
- читаемые опасности;
- красивые тематические фоны;
- плавная анимация крыльев;
- аккуратно вырезанные ассеты;
- звёзды только внутри игры;
- completion state как в других бонусных играх;
- не ломать основную систему AliToDo.
