# Ali Quest / Путь героя — Руководство по разработке и архитектуре

Это руководство (Skill) содержит полное описание архитектуры, структуры данных, игровых движков, а также ключевых тонкостей разработки проекта **Ali Quest (Путь героя)**. Оно предназначено для ввода в контекст новых разработчиков и ИИ-агентов.

---

## 1. Концепция продукта (Product Goal)
Приватный семейный дашборд для двух братьев — Али и Саида. Предназначен для короткого ежедневного ритуала:
* Просмотр и выполнение реальных задач (учеба, спорт, помощь по дому, чтение).
* Получение оценок (синхронизация со школой) и заработок звёзд (с поддержкой дробных до 0.5).
* Магазин наград (выбор награды списывает/замораживает звёзды; родитель подтверждает выполнение в админ-панели).
* Ежедневное аудио/текстовое напутствие от ИИ-наставника (выбранного героя, например, Роналду или Мухаммеда Али) с жестким лимитом (без бесконечного чата).
* Админ-панель родителей защищена 4-значным PIN-кодом (без классической связки email/пароль) с сессией на безопасных cookies.
* Продукт ориентирован на мобильные телефоны, планшеты и десктопы.

## 2. Стек технологий
* **Фреймворк**: Next.js (App Router) + TypeScript.
* **Стилизация**: Tailwind CSS.
* **База данных**: Upstash Redis REST API (через серверные роуты).
* **Хостинг**: Vercel (интегрирован с GitHub для автодеплоя).
* **Уведомления**: Telegram Bot API + Web Push Notifications (VAPID).

## 3. Разделение слоёв данных (Ali vs Said)
Для обеспечения приватности и независимого прогресса данные детей строго разделены на уровне ключей в Redis.
Родительские настройки хранятся в едином ключе `aq:settings`, но содержат отдельные ветки конфигурации.

### Ключевые паттерны в Redis:
* `aq:settings` — общие настройки (включая PIN-коды, флаг включения валюты).
* `aq:children` — список профилей детей с базовой информацией.
* `aq:events:parent` — единая лента уведомлений для родителя (выполненные задачи, выбранные награды).
* `aq:rewards` — глобальный список доступных наград (активные/неактивные, привязка к ребёнку `childId: "ali" | "said" | "both"`).

#### Слой Али:
* `aq:star-ledger:ali` — история начисления и списания звёзд (все изменения баланса происходят строго через добавление записей в этот лог).
* `aq:reward-status:ali` — статус покупок наград Али (`available` / `selected` / `fulfilled`).
* `aq:day:ali:YYYY-MM-DD` — состояние выполнения задач Али за конкретную дату.
* `aq:child:ali:profile` — кастомные настройки профиля Али (например, выбранный ИИ-герой).

#### Слой Саида:
* `aq:star-ledger:said` — лог звёзд Саида.
* `aq:reward-status:said` — статус наград Саида.
* `aq:day:said:YYYY-MM-DD` — задачи Саида за дату.
* `aq:child:said:profile` — профиль Саида (включая режим "little-hero", отключающий отображение школьных оценок).

## 4. Игровые движки бонусных игр
Игры запускаются при открытии карточки заработанной серии побед (Streak Rewards) на главной странице. После успешного прохождения игры кнопка деактивируется (статус сохраняется в БД).

### 4.1 Catcher Game (Ловец предметов)
Кастомный 2D-движок на HTML5 Canvas (размер рендеринга $840 \times 400$ px).
* **Управление**: Персонаж перемещается по горизонтали, плавно следуя за указателем мыши или пальцем на экране с коэффициентом сглаживания (lerp):
  `player.x += (targetX - player.x) * 0.22 * dt`.
* **Поддержка тач-управления**: Обработчик движения `handlePointerMove` повешен не только на `onMouseMove` и `onTouchMove` (ведение пальцем), но также на `onMouseDown` и `onTouchStart` (тапы). Это позволяет персонажу бежать к точке нажатия без мгновенной грубой телепортации.
* **Сетка спрайтов**:
  * Персонажи (Капибара Капи, Буйвол Гром, Носорог Титан) и падающие элементы вырезаются из исходных листов.
  * Ключевое правило: все спрайт-карты скомпонованы в строгие ячейки размером **$418 \times 627$ px**.
  * Верхняя строка ячеек содержит анимацию ходьбы персонажа (кадры 0 и 1), нижняя строка содержит падающие предметы.
  * Размеры в коде игры: персонаж отрисовывается в пропорциях `73x110` px, падающие элементы — `46x69` px.

### 4.2 Runner Game (Бег с препятствиями)
Классический бесконечный раннер. Управление осуществляется тапом/кликом по экрану в любом месте для прыжка или приседания.

## 5. Узкие места архитектуры и критические ошибки (Bugs & Bottlenecks)

### 5.1 Конфликт сборки Next.js (Webpack Dev Mismatch)
* **Проблема**: Запуск команды `npm run build` (или автодеплой) при параллельно работающем dev-сервере (`npm run dev`) приводит к повреждению кэша компилятора в папке `.next/`. В результате в браузере открывается белый экран с ошибкой `Cannot find module './XXXX.js'`.
* **Решение**: Перед сборкой или при зависании сервера всегда останавливайте процесс dev, очищайте кэш командой `rm -rf .next` и запускайте сервер заново.

### 5.2 Зависание наград в статусе "Selected" (Dangling Lock)
* **Проблема**: Когда ребёнок выбирает награду в магазине, звёзды списываются (-250 ⭐), а статус награды меняется на `selected`. Родителю в историю падает событие. Если родитель случайно удаляет это событие через значок «корзины» (вместо нажатия на красный крестик отмены), событие исчезает из ленты. Награда зависает в статусе "выбрано", а звёзды остаются замороженными навсево.
* **Решение**: В обработчик удаления события `deleteEvent` встроена автоматическая проверка безопасности. Если удаляется событие типа `reward-selected` в статусе `selected`, код принудительно возвращает звёзды ребёнку через Ledger (+250 ⭐) и возвращает статус награды в `available`.

### 5.3 Конкурентные запросы к Star Ledger (Race Condition)
* **Проблема**: Баланс звёзд рассчитывается динамически как сумма (`reduce`) всех записей из ключа `aq:star-ledger:childId`. При одновременном выполнении нескольких задач на клиенте могут одновременно улететь POST-запросы на запись. В итоге один из запросов перетирает данные другого.
* **Решение**: Клиентские вызовы API баланса и начисления наград должны выполняться последовательно (например, через `await Promise.all` или дожидаясь ответа сервера) для избежания перезаписи массива в Redis.

### 5.4 Координаты нарезки спрайтов (Sprite Bleeding)
* **Проблема**: Неправильные математические пропорции при делении исходного листа спрайтов приводят к тому, что у персонажей срезаются ноги, а сверху падающих предметов торчит пиксельный мусор от соседних элементов.
* **Решение**: Использовать строго сетку $418 \times 627$ px. Все исходные изображения персонажей предварительно обрабатываются Python-скриптом с помощью анализа связанных областей (connected components) для центрирования каждого спрайта строго в своей ячейке.

## 6. Руководство по операциям и запуску

### Запуск в режиме разработки:
```bash
# Удалить старый кэш
rm -rf .next
# Запустить Next.js
npm run dev
```

### Запуск сборки:
```bash
npm run build
```

### Корректировка базы данных (откат ошибок):
В папке `scripts/` находятся полезные утилиты для исправления данных напрямую в Redis (используют авторизацию из `.env.local`):
* `revert-reward-db.py` — безопасный скрипт для отката ошибочных покупок наград и возврата звёзд.
* `inspect-db.py` — скрипт для проверки текущего баланса, истории транзакций и событий.
