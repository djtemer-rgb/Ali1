## Ключевое правило целостности

Не делай точечные изменения “в одной вкладке”, которые ломают другую.

Перед изменением любого общего surface:

1. найди все связанные файлы;
2. проверь dependency impact;
3. посмотри, что использует этот route/component/API;
4. измени согласованно всю связку;
5. проверь переходы и refresh на соседних страницах.

## Что особенно важно не ломать

- общий дизайн shell;
- loading/error/not-found fallback;
- навигацию между вкладками;
- parent login / parent auth flow;
- child profile switching;
- shared data contract;
- build и production preview.

## Перед завершением

Обязательно:

1. обнови SocratiCode index;
2. проверь, что изменённые маршруты открываются;
3. проверь, что соседние маршруты не сломались;
4. напиши короткий отчёт:
   - что сделал;
   - что сломать удалось избежать;
   - что осталось;
   - какие файлы поменял.

## Формат ответа

Кратко и по делу:

- root cause
- what changed
- how verified
- residual risks
- next safe step
