## 2. Использование архитектуры прошлых игр

Игра полностью интегрирована в существующий каркас бонусных игр:
- **Game Shell / Modal:** вертикальный адаптивный контейнер с ограничением по ширине `max-w-[450px]`, идеально встраивающийся как на экраны телефонов, так и по центру планшетов/ноутбуков.
- **Интеграция с базой данных:** При победе отправляется запрос на `/api/bonus-games` для фиксации завершения бонусной игры для конкретной карточки и ребенка. Кнопка «Бонусная игра» на карточке становится неактивной со статусом «Игра пройдена 🏆».
- **Общий интерфейс HUD:** Стартовый экран, Пауза, экран Победы, экран Поражения (по жизням или таймеру) реализованы в едином дизайне с использованием плавных градиентов и эффектов.

## 3. Физика и механика прыжков

- **Авто-прыжки:** Герой постоянно движется под действием гравитации `g = 0.38`. При падении на платформу (проверка `vy > 0` и координаты ног игрока пересекают верхний край платформы) срабатывает упругий прыжок с импульсом `vy = -12.5`.
- **Управление движением:** Игрок плавно ведет пальцем по экрану (или двигает мышкой), задавая `targetX`. Персонаж сглаженно интерполирует свои координаты к этой точке (`player.x += diffX * 0.16`). Дополнительно поддерживаются мгновенные тапы по экрану для резкого перемещения.
- **Отражение по горизонтали (Mirroring):** 
  Реализована динамическая смена направления взгляда героя. Если цель движения игрока левее текущей позиции персонажа, спрайт отражается по горизонтали на холсте через `ctx.scale(-1, 1)`. При движении вправо спрайт рендерится в обычном виде.
- **Индикация направления:** При активном перетаскивании на холсте рисуется аккуратная пунктирная линия от героя к точке пальца, что помогает ребенку лучше ориентироваться на ходу.

## 4. Генерация платформ и препятствий

- **Гарантированная проходимость:** Уровни генерируются процедурно. Каждая следующая платформа ставится по высоте с шагом в `120-155px` (высота прыжка героя с `vy=-12.5` составляет `h = vy^2 / 2g = ~200px`, что делает каждую платформу легко досягаемой). Горизонтальное смещение между платформами ограничено физическим радиусом прыжка персонажа.
- **Разнообразие элементов:**
  - Обычные платформы.
  - **Движущиеся платформы** (постоянно курсируют влево-вправо, усложняя тайминг прыжка).
- **Звёзды и Бомбы:**
  - Звёзды парят прямо над платформами для сбора.
  - Опасные бомбочки парят в стороне или между платформами на безопасном расстоянии, чтобы всегда была возможность их облететь.
- **Контрольные точки (Checkpoint):** При падении ниже экрана игрок теряет одну жизнь и возрождается на ближайшей безопасной платформе над зоной падения.

## 5. Вырезание ассетов и хромакей

Спрайтшиты были обработаны Python-скриптом с использованием Pillow:
1. Автоматически определялся цвет хромакея по верхнему левому пикселю (зеленый или маджента).
2. Применялось удаление хромакея с порогом `tolerance = 45`.
3. Использовано подавление цветового шума по краям (spill suppression) для создания мягких переходов без зеленых/розовых ореолов вокруг ушей, хвостов и шерсти.
4. Выполнялся динамический поиск горизонтальной линии раздела строк спрайтшита (`Y-split`) для корректной нарезки.
5. Вырезанные кадры автоматически центрировались по горизонтали и прижимались к низу в стандартных ячейках `418x627` для полной соосности анимационных кадров.

## 7. Риски и рекомендации на будущее

- **Балансировка высоты:** Текущая высота уровня составляет `4600px` (около 30-35 платформ). На прохождение уходит ~35 секунд. При необходимости её можно легко увеличить или уменьшить в `JumpGame.tsx` через переменную `levelHeight`.
- **Сенсорное управление:** На некоторых старых Android-устройствах `onTouchMove` может вызывать нативный скролл страницы. Мы предотвратили это с помощью селекторов `touch-none` и `select-none` в CSS, но на реальных устройствах рекомендуется дополнительно протестировать отзывчивость.
